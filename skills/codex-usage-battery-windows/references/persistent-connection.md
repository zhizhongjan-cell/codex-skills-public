# 持续连接、时钟和周额度

## 显示含义

主电池仍显示主要额度剩余百分比。右侧时钟显示下一次主动校对时间，本周剩余仅取长度为10080分钟的实际额度窗口。没有该窗口时显示未知，不用其他窗口代替。

“下次”表示主动读取计划，不是额度重置时间；官方通知可能提前更新数值。查询期间显示“正在更新”，失败期间显示“重试”及预计时间。重置时间、最近数据时间和独立周额度采样时间在悬停说明中。数据过期或失败不会冒充新数据。

## 连接规则

- Codex窗口就绪后启动一个工具自己的 `codex.exe app-server`，初始化一次，保持私有stdio连接。正常30秒补查、手动刷新、切回Codex均复用该连接。
- 接收 `account/rateLimits/updated`，仅接受codex桶。字段级合并：省略保留、显式null清空；其他桶不能覆盖数据或刷新时间。
- 同时最多一个未完成RPC。账户状态变化会清空缓存并增加代际；旧在途请求收尾后丢弃结果，再读取新账户数据。
- 普通RPC错误在同一连接上按5、10、20、40、60秒上限退避；手动/自动刷新不能绕过退避。局部通知不清除主动读取的故障与累计退避。
- EOF、协议异常或20秒超时才关闭本工具的子进程并退避重连。只清理自己创建的进程，不枚举杀死官方Codex服务。
- 关闭最后一个窗口时停止计时、取消未完成读取、退出查询子进程和电池。没有登录常驻进程。

## 同步边界

数据来自官方 `account/rateLimits/read` 和连接内通知，不是读取官方界面或监听同一桌面私有消息流。其他桌面会话产生的变化是否会推送到此连接，取决于服务端行为，因此保留30秒校对；不能承诺与官方界面零延迟一致。

主额度与周额度有独立采样时间。只有主额度通知时不让旧周额度重新变“新”；断网、过期及账户变化须标明。系统时间跳变、官方后台延迟也可能影响显示时刻，用户可右键刷新。

## 验证

`Test-Runtime -Suite Full`：原46项功能检查，外加33项持久连接/部分通知/账户切换/退避/取消检查及进程复用回归，共80项。假服务和编译产物放入新的隔离测试目录，不更改真实CLI配置，不登记任务。

`-Suite Live`：等待至少3次读取（最长95秒）真实连接，至少3次读取、进程启动计数为1，结束后查询子进程退出。它不关闭真实Codex，不发起模型对话，也不证明下一次Windows开机或跨机器兼容。

公开分发只带测试源码，不带假服务exe、本机探测结果、真实额度或日志。
